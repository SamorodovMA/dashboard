# 📦 Dashboard сверки расписания доставки

Независимый инструмент для сверки настроек доставки между Axapta (Dynamics AX) и сайтом (чекаут).

## Проблема (боль)

### Текущий процесс проверки настроек

В компании существует **GEO-мониторинг** — автоматизированная система, которая 4 раза в день прогоняет тестовые кейсы и присылает Telegram-отчёт с результатами. Однако у GEO-мониторинга есть критическое ограничение:

- **GEO работает только для склада Коптево**. Для остальных доноров (Сум, Браст, ДЛТ, Оксмер, Бутики) автоматизированной проверки нет.
- Настройки доставки проверяются **«раз в пару-тройку недель»** — вручную на сайте (чекауте).
- Когда обнаруживается расхождение между ожидаемой и фактической датой доставки, **непонятно, на чьей стороне проблема**:
  - В настройках Axapta (неправильное расписание, капаситет, привилегия)?
  - В ручной ошибке тестового кейса GEO?
  - В чекауте (сайте)?

### Как проверяют сейчас

Чтобы проверить расчёт, логисты вынуждены:
1. Заходить в уже созданные заказы в Axapte
2. Смотреть, какие даты проставились
3. Сравнивать с тем, что показывает сайт
4. Пытаться понять, где ошибка

Это неудобно, долго и не даёт ответа на вопрос «кто виноват».

## Цель проекта

Создать **независимый дашборд**, который станет единым источником правды для сверки настроек доставки:

1. **Независимый расчёт напрямую из Axapta** — логист задаёт параметры (товар, донор, склад, способ доставки, карта, привилегия) и получает плановые даты, рассчитанные Axapta в реальном времени
2. **Детализация по этапам**: подбор → перемещение → упаковка → ПДО → ПДД (дата + интервал)
3. **Работа для всех доноров**, а не только для Коптево
4. **Ускорение диагностики расхождений**:
   - Если расчёт дашборда **совпадает** с кейсом GEO → проблема в ручной ошибке кейса
   - Если расчёт дашборда **не совпадает** с кейсом GEO → проблема в настройках Axapta
   - Если расчёт дашборда **не совпадает** с чекаутом → проблема в чекауте
5. **Замена ручной проверки на сайте** единым интерфейсом

### Процесс сверки

```
Логист задаёт параметры в дашборде
          │
          ▼
Дашборд отправляет запрос в Axapta (REST API)
          │
          ▼
Axapta рассчитывает этапы с учётом:
  • настроек расписаний
  • капаситета складов
  • привилегий клиента
          │
          ▼
Дашборд показывает результат:
  • ПДД (дата + интервал)
  • Детализацию по этапам
          │
          ▼
Логист сверяет с:
  • данными GEO-мониторинга (Telegram-отчёт)
  • данными с чекаута (сайт)
          │
          ▼
Вывод: проблема в кейсе GEO, в настройках Axapta или в чекауте?
```

## Функциональность

### Фильтры (входные параметры)

| Параметр | Описание | Пример |
|----------|----------|--------|
| **Товар** | Артикул тестовой позиции, которая есть на всех донорах | `TEST-001` |
| **Группа доноров** | Склад, с которого забираем товар | Коптево, Сум, Браст, ДЛТ, Оксмер, Бутики |
| **Склад комплектации** | Склад, на который свозим товар | КоптИнтмаг, ИнтМаг, ДИнтМаг |
| **Тип доставки** | Способ получения клиентом | ССД (курьер), ПВЗ (самовывоз) |
| **Код способа** | Конкретный код с описанием (город, тип доставки) | `112b` — VIP Москва ССД БД |
| **Тип карты клиента** | Уровень карты лояльности | White, Orange, Black |
| **Привилегия** | Дополнительные привилегии клиента | VIP_online, Orange+, Black и др. |
| **Тестовая позиция** | Режим расчёта по всем донорам сразу | вкл/выкл |

### Детализация расчёта по заказу

Отдельный блок для просмотра уже готового расчёта по конкретному заказу из Axapta.

| Параметр | Описание | Пример |
|----------|----------|--------|
| **Номер заказа** | Номер заказа в системе Axapta | `AX-2026-001234` |

При вводе номера заказа дашборд запрашивает у Axapta готовый расчёт по этому заказу и отображает:
- **Информацию о заказе**: товар, донор, склад комплектации, тип доставки, код способа, карта, привилегия
- **Детализацию по этапам**: подбор → перемещение → упаковка → ПДО → ПДД с датами и кодами расписаний
- **Плановую дату доставки**

Это позволяет логисту быстро посмотреть детализацию по конкретному заказу, не заполняя фильтры.

### Результаты (выходные данные)

- **Плановая дата доставки (ПДД)** — календарь на 7 дней с выбором даты и временного слота
- **Детализация расчёта** — таблица этапов по каждому донору:
  - **Подбор** — дата/время начала и окончания подбора на доноре
  - **Перемещение** — дата/время перемещения с донора на склад комплектации
  - **Упаковка** — дата/время упаковки на складе комплектации
  - **ПДО** — предварительная дата отгрузки (только начало)
  - **ПДД** — плановая дата доставки с интервалом (только начало)
- **Информационная панель** — выбранный склад, тип доставки, код способа

### Адаптивность

- Десктоп (≥900px) — полная версия с таблицей
- Планшет (768–900px) — компактные фильтры
- Телефон (480–768px) — таблица в виде карточек
- Маленький телефон (≤480px) — всё в колонку
